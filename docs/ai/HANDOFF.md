## C1. Technical model of the libc pool problem (root cause UNKNOWN)
After ~100-160 s of play (earlier on a 2nd round in the same process) pthread_mutex_init / cond_init / attr_init return ENOMEM (12) = "CLIFF" (`pool: CLIFF reached here`). The pool is dynamic (cliff at ~995-1180 attr inits, 45-85 threads); destroying mutexes doesn't move it. Handled by fallbacks in ps5lwjgl.c (`#ifdef PS5_VK` region; `__wrap_X` symbols in liblwjgl_ps5.a are auto-converted to --wrap=X by make_jvm_title.sh ~l.227 and vk_relink.sh; `__real_X` weak, plain libc fallback in sandbox):
1. attr_init: 50 retries -> reserve of AT_RES=96 real attrs (memcpy) -> zeroed stand-in (stand-in threads overflow HotSpot's assumed 512KB stack, so the reserve matters). Wrappers for attr_get_np/getstack/getstackaddr/getstacksize/destroy/setstacksize + weak __wrap_pthread_create (stand-in -> __real_pthread_create(t,0,f,arg)+detach). Zero-attr thread gets cpuset 0 = never scheduled.
2. cond_init: reserve CV_RES=96.
3. mutex_init: reserve MX_RES=512 real mutexes (new, UNTESTED). Old behaviour (share a donor mutex per call site) aliased unrelated HotSpot Monitors -> 13-52 s "WHOLE JVM STOPPED" and permanent freeze at save-and-exit; sharing is now only last resort, then zeroed mutex.
4. pthread_setspecific/getspecific fallback table (SS_N=256, keyed by pthread_self+key) because threads without TLS had NULL Thread::current() (sig=11 addr=238 in resource_allocate_bytes). Ca. confirmed: game survives the cliff and worker-thread restart.
5. `__wrap_setlocale` returns "en_US.UTF-8" (UTF-8 file names on all JDKs; patch25 used "C").
6. Probes: `pool:` line (mutex alive/made/destroyed/shared, attr made/failures, threads seen, TLS fallback, can-still-make rc), `slowframe:` (frame time outside swap + sample_all_threads stacks), `stall:`, `loaders:` (McBoot LinkageError probe), `mem:`; CRASH sig=30 blocks are stack SAMPLES, sig=11 real crashes; "SAMPLE #N NO ANSWER (affinity 0)" = dead/stale registered thread (probe artifact). libc module is at 0x8xxxxxxxx (rip=8000a870d = libc offset 0xa870d; 80000038c = umtx wait).

## 3. How the return-to-launcher works now (exitmarks-4) - read before touching McBoot
- The console refuses the process-exit syscall (SIGSYS at the libkernel stub); restart APIs (sceSystemServiceLoadExec/LaunchApp) never produced a visible result; the title can only end at the PS5 home screen. So the VM never exits: `System.exit` is intercepted by a SecurityManager (`installExitGuard`, `-Djava.security.manager=allow`, added by jvm_host.cpp when JDKV_N < 24; make_jvm_title.sh writes `#define JDKV_N` into ps5_conf.h). checkExit -> elog + leave(why, spawn) then throws ExitGuard (a SecurityException) to unwind the game's thread; `playOnce()` returns "exit".
- First leave() (from the VM main thread or any non-relaunch thread) starts the single "ps5-relaunch" thread (64 MB stack); its loop: wait for `gameDone`, playOnce() (= Hello.glCompat(0), Launcher.runQueue, Kit.show, version pick, chooseGl, class loader, shutdown hook once, started=true, ENDED=false, gameDone=false, main.invoke), finally glCompat(-1) releases the GL context and sets gameDone. Run() on the VM main thread parks forever after leave (returning from Hello.main would end the title).
- Other triggers of leave(): shutdown hook (parks), exit-watch thread (Hello.soundDownAt set by the Java Hello.log wrapper when MC logs "SoundSystem shutting down"; leaves 3.5 s later if nothing happened), PS5Display.destroyWindow daemon "ps5-closing" (1.5 s, reflection on McBoot.leave), MC crash/return. ui=off in launcher.cfg uses the old native steps (leaveProcess: Hello.exitStep(0..5)); crashes still go through the native crash() -> quit_request -> return_to_launcher (restarts the title, works only if process age >= 12 s).
- GL context model (ps5lwjgl.c): one fixed EGL window/context; glfwCreateWindow again returns the existing window; glfwDestroyWindow is a no-op; ps5_gl_release() (called by Kit at its end, by n_disp_destroy for LWJGL2, and by the game thread's finally) resets swap interval to 1 and the shim's input state, then eglMakeCurrent(NONE). glfwMakeContextCurrent configures gl4es once (`ps5g4_ready`) for glcompat level 21 (<=1.16.5). Hello.glCompat(level): 0 core, 21 gl4es fixed-function, -1 release context.
- UDP log loss: lines near process end and in startup bursts get dropped. Java `Hello.log` lines are mostly reliable, native kit_log/`[jvm]` lines and `[prev]` replay are not; `Hello.mark` writes synced marks (.kit/exitmark.txt, printed as `prev:` at the next start). Build stamps: jvm_host back2l-12, McBoot exitmarks-4 (sed'd after the log; the user's log of the next build should say exitmarks-4).
